## 结果

1. API 健康、注册和登录通过。
2. 小作者的已发布作品超过 100 条时，准确回填最近 100 条，排除隐藏/无发布时间视频，排序正确且 Redis 有效期至少 29 天。
3. 16 次并发同幂等键关注重试均成功；关系行仍一条、关注数仍为 1、收件箱仍为 100 条。
4. GET/POST 关注流前两页与数据库排序一致；匿名请求返回 401，其他用户看不到该用户作品索引。
5. 取关后即使 Redis 保留旧成员，关注流不再展示这些作品。
6. 大作者关注前统计为 9999，关注后为 10000；通过 `/api/relations/{targetUserId}` 关注不回填，验证另一关注路由与阈值边界。
7. 将测试用户收件箱注入错误 Redis 类型，关注返回统一 500，数据库关注状态仍为有效；Feed 在缓存错误时回源成功。清除故障后使用原幂等键重试，收件箱恢复 100 条，关注数未重复增加。
8. 预置超过容量的收件箱成员后再次回填，真实 Redis 事务将容量裁剪至 1000。

## 测试脚本修正与边界

工作区原有失败记录中的大作者用例只执行 UPDATE；新账号尚无统计行，导致阈值未设置。本次改为 INSERT ... ON CONFLICT，并在发起关注前断言统计确为 9999。重新执行后全部通过，无需修改业务代码。

测试作品使用占位媒体 URL，部分作品及阈值统计直接写入隔离数据库以构造边界；未验证浏览器播放或一万名真实粉丝。RabbitMQ 随应用运行，但本次结果不代表对其全部消息语义做了独立验收。
