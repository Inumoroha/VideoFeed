## 一、Redis 配置与时间线索引

- 补充 Redis 地址、密码、数据库编号、连接池大小和最小空闲连接数配置。
- 完善 Redis 配置校验，覆盖地址缺失、数据库编号越界和连接池参数非法等情况。
- 为时间线查询增加 `(status, published_at, id)` 复合索引，匹配已发布视频按发布时间和 ID 倒序分页的查询路径。
- 将时间线索引交由视频 GORM 模型和 `AutoMigrate` 统一维护，避免 Feed 仓储承担数据库结构初始化职责。

## 二、时间线 Feed 读缓存

- 为 `scene=timeline` 接入 Redis 读缓存；Redis 未配置时保持原有 PostgreSQL 查询流程。
- 首页缓存有效期以 5 秒为基准，后续页以 45 秒为基准，并按缓存键增加稳定抖动，降低缓存同时失效造成的回源压力。
- 缓存键包含分页大小；后续页使用游标的 SHA-1 摘要，避免把完整游标写入 Redis 键名。
- 使用 `singleflight` 合并同一进程内相同缓存键的并发回源请求。
- 共享回源查询使用独立的 5 秒超时，单个 HTTP 请求取消只终止自身等待，不会取消其他请求共享的查询。
- 缓存读取或写入失败时降级访问 PostgreSQL，缓存故障不改变 Feed 接口的数据库错误语义。
- 增加缓存回归测试，覆盖并发合并、请求取消、缓存异常降级和不同 Feed 场景隔离。

## 三、Web 信息流修复

## 四、容器化部署

- 增加前端多阶段 Docker 构建，使用 Nginx 提供生产静态资源。
- 配置 Nginx 将 `/api/` 和 `/uploads/` 转发到 API 服务，并将上传体积限制设置为 `1024m`。
- 增加后端多阶段 Docker 构建，以 `cmd/server` 作为编译入口并暴露 `9000` 端口。
- 在仓库根目录增加 Compose 编排，统一启动 PostgreSQL 17、Redis 7.4、Go API 和 Web 服务。
- 为 PostgreSQL、Redis 和 API 配置健康检查及依赖顺序，并为数据库、Redis 和上传文件配置持久化数据卷。
- 增加容器环境专用配置和 Docker 构建忽略规则，支持通过环境变量覆盖数据库连接和 JWT 密钥。
